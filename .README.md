# dotfiles-yadm

Mis dotfiles, gestionados con [yadm](https://yadm.io) (un repo git "bare" cuyo
work-tree es `$HOME`). Pensado para Arch Linux.

> Este archivo es `.README.md` (oculto a propósito) para que no ensucie `$HOME`
> al hacer checkout. GitHub no lo muestra en la portada del repo; léelo desde
> el propio repo o en
> <https://github.com/1noro/dotfiles-yadm/blob/main/.README.md>.

## 1. Instalación en un Arch recién instalado

```bash
# 1. yadm y lo mínimo para clonar/firmar
sudo pacman -S --needed yadm git openssh gnupg

# 2. Clonar por HTTPS (el repo es público, no hace falta clave SSH todavía)
yadm clone https://github.com/1noro/dotfiles-yadm.git

# 3. En una instalación fresca ya existen .bashrc y .bash_profile (de /etc/skel),
#    así que yadm avisará de conflictos. Para quedarte con los del repo:
yadm checkout "$HOME"

# 4. Pasar el remote a SSH para poder hacer push (cuando ya tengas la clave en GitHub)
yadm remote set-url origin git@github.com:1noro/dotfiles-yadm.git

# 5. Comprobar que está todo limpio
yadm status
```

### Antes del primer commit: restaurar la clave GPG

`.gitconfig` tiene `commit.gpgsign = true` y `signingkey = 224E59DC1CF60B98`.
Sin esa clave, **cualquier `yadm commit` falla**. Importa tu clave privada
desde tu backup (`gpg --import clave.asc`) o cambia la firma en `.gitconfig`.

### Lo que NO está en el repo (hay que restaurarlo a mano)

| Qué | Dónde / por qué |
|---|---|
| Claves SSH y `~/.ssh/config` | Secretos. Los scripts `i2p-up` / `i2p-down` esperan un host SSH llamado `i2p` en ese config. |
| Clave GPG | Ver arriba. |
| `~/.bashrc_ext` | Config específica de cada máquina (el `.bashrc` lo carga si existe). En el repo solo está `bashrc_ext.d/mpu.sh`. |
| `~/repos/home-scripts` | `~/.bin/scripts` es un symlink a `~/repos/home-scripts/scripts`. Clona ese repo y recrea el enlace: `ln -s ~/repos/home-scripts/scripts ~/.bin/scripts`. |
| `~/.config/rclone`, `~/.config/mutt/muttrc`, `~/.aws`, `~/.kube`, `~/.docker`, `.claude.json`, … | Contienen credenciales: están en el `.gitignore`. |
| `~/.config/opencode/` | Ignorado: opencode lo reescribe en cada arranque. |
| `~/.local/share/fonts/` | Fuentes: se instalan por paquete (ver abajo). |
| Montaje NFS `/nfs/Music` | `beets` guarda ahí la biblioteca y los logs (`.config/beets/config.yaml`). |

## 2. Qué instalar antes (o justo después) de aplicar los dotfiles

### Imprescindible (si falta, algo se rompe)

```bash
sudo pacman -S --needed \
  alacritty zellij \
  neovim git curl \
  starship fzf eza lf \
  ttf-jetbrains-mono-nerd
```

| Paquete | Para qué |
|---|---|
| `alacritty` | Terminal (`.config/alacritty/alacritty.toml`). |
| `zellij` | **Crítico**: alacritty lo arranca como shell (`[terminal.shell] program = "zellij"`). Sin él la terminal no abre. También su `config.kdl`. |
| `ttf-jetbrains-mono-nerd` | Fuente de alacritty (`JetBrainsMono Nerd Font Mono`) e iconos de `lf`/`starship`. Los ajustes de render están en `.config/fontconfig/fonts.conf`. |
| `starship` | Prompt (`.bashrc`: `eval "$(starship init bash)"`, config en `.config/starship.toml`). |
| `fzf` | `cd-fzf`, `cd-fzf-repos` (atajo `Ctrl+Espacio`), `dbash`, `pacman-fzf`. |
| `eza` | `.bashrc` llama a `exa` en las previews de fzf; en Arch `eza` provee `exa`. Si no, instala un alias/symlink `exa -> eza`. |
| `lf` | Gestor de archivos (`.config/lf/`, y la función `lf` de `.bashrc` que hace `cd` al salir). |
| `neovim` | `$EDITOR`/`$VISUAL` (en `.bash_profile`) y alias `v`, `vc`. |
| `git`, `curl` | Necesarios para vim-plug (ver §3). |

### Herramientas de desarrollo y shell (las usan alias/funciones del `.bashrc`)

```bash
sudo pacman -S --needed \
  docker docker-compose \
  rustup go \
  yt-dlp \
  mpv htop neofetch \
  shellcheck shfmt \
  open-dyslexic-fonts \
  xdg-utils
```

| Paquete | Para qué |
|---|---|
| `docker`, `docker-compose` | Alias `di`, `dps`, `dlog`, y funciones `dbash`, `dbrash`, `dirn`. Después: `sudo systemctl enable --now docker` y `sudo usermod -aG docker $USER`. |
| `rustup` | `.bash_profile` y `.profile` cargan `~/.cargo/env`. Luego: `rustup default stable`. |
| `go` | `.bash_profile` define `GOPATH=$HOME/go`. |
| `yt-dlp` | Alias `yt` y `yt2mp3`; también lo usa `mpv` (`ytdl-raw-options`). |
| `mpv` | `.config/mpv/`. Usa la fuente **OpenDyslexic** para los subtítulos → `open-dyslexic-fonts`. |
| `htop` | `.config/htop/htoprc`. |
| `neofetch` | Su config no está en el repo, pero lo usas. (Está descontinuado; `fastfetch` es el relevo.) |
| `shellcheck`, `shfmt` | Linters/formateadores que referencia `.config/nvim/coc-settings.json`. |
| `xdg-utils` | `xdg-open`, usado por `lf` y `.mailcap`. |

Otros del entorno (de `.bash_profile`): `evince` (`READER`), `sxiv` (`IMAGE`),
`firefox` (`BROWSER`).

### Node (nvm)

`.bashrc` carga `nvm` desde `/usr/share/nvm/init-nvm.sh` o, si no existe,
desde `~/.nvm`. Dos opciones: el paquete **`nvm` del AUR**, o el script oficial
de <https://github.com/nvm-sh/nvm>. Después: `nvm install node`.

### Música (beets)

```bash
sudo pacman -S --needed beets python-pylast python-requests python-pillow imagemagick python-flask
```

Plugins activos: `musicbrainz fetchart embedart`. `python-flask` solo hace
falta si reactivas el plugin `web` (ahora comentado). Monta antes `/nfs/Music`.

### Audio (PipeWire)

```bash
sudo pacman -S --needed pipewire pipewire-pulse wireplumber pavucontrol
systemctl --user restart pipewire wireplumber
```

`.config/pipewire/pipewire.conf.d/high-quality.conf` fuerza las frecuencias
44.1/48/96/192 kHz.

### Otros que usas y están referenciados

| Programa | Notas |
|---|---|
| `brave-bin` (AUR) | Flags de Wayland/aceleración en `.config/brave-flags.conf`. |
| `telegram-desktop` | Lo cierra el script `~/.bin/telegram-kill`. |
| `opencode` | Se instala con su script oficial (queda en `~/.opencode/bin`, ya en el `PATH` del `.bashrc`). Su config no se trackea. |
| `rclone`, `pandoc-cli`, `mediainfo`, `ffmpeg`, `tldr` | Aparecen mucho en tu historial de bash; no hay config en el repo. |

### `lf`: previsualización (opcional)

El script `.config/lf/preview` usa `bc`, `poppler` (`pdftoppm`), `unzip`,
`unrar`, `7zip`, y un script `~/.config/lf/image` (con ueberzug o similar) que
**no está en el repo**. Además, `previewer` está comentado en `lfrc`, así que
de momento no es necesario.

## 3. Pasos de post-instalación

1. **Neovim, plugins:** instala vim-plug y luego los plugins.
   ```bash
   curl -fLo ~/.local/share/nvim/site/autoload/plug.vim --create-dirs \
     https://raw.githubusercontent.com/junegunn/vim-plug/master/plug.vim
   nvim +PlugInstall +qall
   ```
   (`.config/nvim/plugged/` está ignorado: se regenera con esto.)
2. **Rust:** `rustup default stable`.
3. **Node:** `nvm install node` (ver arriba).
4. **Cachés de fuentes:** `fc-cache -fv` tras instalar las fuentes.
5. **Cierra sesión y vuelve a entrar** (para `environment.d/`, `.profile` y el `PATH`).
6. Abre alacritty: debería arrancar zellij con tu prompt de starship.

## 4. Uso diario

`yadm` funciona como `git`, pero con `$HOME` como work-tree:

```bash
yadm status
yadm add ~/.config/loquesea
yadm commit -m "feat(x): ..."      # requiere la clave GPG
yadm push
yadm list -a                       # archivos trackeados
```

Todo lo no trackeado está ignorado por defecto salvo lo que añadas
explícitamente. Revisa el `.gitignore` antes de añadir cosas nuevas (el repo
es **público**): ahí hay patrones para claves, tokens y backups.

Documentación: <https://yadm.io/docs/common_commands>
